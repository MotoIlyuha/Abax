# AGENTS.md — Правила автономной разработки Abax

Ты — автономный Senior TypeScript-инженер, работающий над экосистемой **Abax Board** и **Abax Tutor**.

## 1. Архитектурные инварианты (НАРУШАТЬ ЗАПРЕЩЕНО)
1. **Zero UI Frameworks в `src/`**: только чистый TypeScript и нативный DOM/Canvas 2D API. Не устанавливай React, Vue, Zustand, Tailwind или внешние стейт-менеджеры.
2. **Иммутабельность элементов доски**:
   - Массив `state.board.elements` обновляется через `replaceElements()` / `addElement()` / `deleteSelected()` в `src/state.ts`; кэш отрисовки (`WeakMap` по ссылке в `src/renderer.ts`) и `src/spatial-index.ts` опираются на то, что элементы не правятся на месте.
   - Любое пользовательское изменение на холсте обязано вызывать `pushHistory()` перед мутацией для работы Undo/Redo. Исключения (реакции, комментарии, ввод ученика в задание) — см. Locked Decisions в `SPEC_NIGHT1.md` … `SPEC_NIGHT6.md`.
3. **Сериализация и валидация (`src/file.ts`, `src/geom.ts`, `src/renderer.ts`)**: при добавлении новых полей в `BaseEl`, `Page`, `Project` или нового типа в union `Element` (`src/types.ts`) обязательно обновить:
   - `sanitizeElement` / `parseProject` в `src/file.ts` (чтобы поля не стирались при сохранении/загрузке),
   - `elementAABB` и `hitTest` в `src/geom.ts`,
   - `drawElementBody` в `src/renderer.ts`.
4. **Безопасность (Strict CSP)**: никогда не используй `innerHTML` для данных пользователя или сетевых пакетов. Используй `document.createElement` и `textContent`.
5. **Язык**: весь текст интерфейса и комментарии — на русском языке.
6. **Стили** — в `src/style.css`, разметка каркаса — в `index.html`.

## 2. Команды проверки качества
После каждого изменения запускай:
- `npm run typecheck` — проверка типов фронтенда (`tsconfig.json`)
- `npm run typecheck:tests` — проверка типов тестов (`tsconfig.test.json`)
- `npm test` — все unit и серверные тесты (Vitest)

Задача НЕ считается выполненной, если хотя бы одна из этих трёх команд завершается с ошибкой. Сквозные тесты (`npm run test:e2e`, Playwright) — на последней задаче ночи и для затронутых спеков.

**Зависимости**: новые npm-пакеты (`dependencies` и `devDependencies`) и вендорные библиотеки не добавляются без явного решения пользователя в Locked Decisions (Ночь №6: «0 новых зависимостей»).

## 3. Автономный ночной режим
- В ночном режиме НЕ задавай вопросов пользователю.
- При неоднозначности сверяйся с `SPEC_NIGHT6.md` (Ночь №6, раздел 11 Locked Decisions; предыдущие — `SPEC_NIGHT5.md` … `SPEC_NIGHT1.md`). Если ответа там нет — выбирай самое простое обратно-совместимое решение, документируй его в `NIGHT_LOG.md` и продолжай работу.
- После завершения каждой задачи из `TASKS.md` отмечай чекбокс `[x]`, записывай краткий отчёт в `NIGHT_LOG.md` и делай атомарный `git commit`.
- Старт ночи (ветка, журнал, первый коммит) — по п. 0.1 Locked Decisions текущей спецификации. Журнал прошлой ночи переименовывается в `NIGHT_LOG_NIGHT<N>.md`.

## 4. Сервер (`server/`, Ночи №3–6)
- Каталог `server/` — Node + TypeScript + `better-sqlite3`; он импортирует из `src/` только чистые модули без DOM (`types`, `file`, `delta`, `limits`, `task-element`, `room-host`, `asset-store`, `project-access`, `cursors`, `sync-conflict`, `room-chat`, `board-url`, `comments`, `collab-transport`, `access`, `element-guard`).
- Клиент без настроенного адреса API (`apiUrl`) не делает сетевых запросов: все старые тесты работают как раньше.
- Серверные тесты — `tests/server/*.test.ts` (`createAppServer({ dbPath: ':memory:' })`); типы сервера проверяет `npm run typecheck:tests`.

## 5. Профиль и курсоры (Ночь №4)
- Каталог курсоров `src/cursors.ts` — единственный источник пресетов; SVG курсоров строится только из констант каталога (никаких пользовательских данных в разметке). Белый список идентификаторов в `electron/room.cjs` должен совпадать с каталогом (тест паритета).
- Модальное окно первого входа не должно мешать тестам: E2E кладут готовый `doska.profile` (`onboarded: true`) через `addInitScript`.

## 6. Совместная работа (Ночь №5)
- Протокол хабов меняется только одновременно в `src/room-host.ts` и `electron/room.cjs`, с одинаковыми сценариями тестов для обоих.
- Чат комнаты — только в памяти хаба (буфер 100), не в проекте, файле и БД; текст сообщений и ссылки выводятся только через `textContent`.
- Снимок участников строится на получателя: участник на скрытой для получателя странице приходит с `hiddenPage: true` без страницы, курсора, камеры и выделения.

## 7. Доступ и защита элементов (Ночь №6)
- Итоговое право на странице и возможности участника считаются только функциями `src/access.ts` (`effectivePageAccess`, `participantCaps`); REST (`server/projects.ts`, `server/invite-routes.ts`), облачная комната и оба хаба вызывают их же (в `electron/room.cjs` — копия с тестом паритета). Скрытая кнопка в интерфейсе — не защита: каждое ограничение обязано проверяться хабом или сервером.
- Владелец — только `isOwner` по проверенной сессии (`user.id === owner_id`) → `isHost`. Никакая роль, токен или ссылка не дают `isHost`, ответы заданий, изменение `permissions`, удаление доски или управление тарифом.
- Старые роли `edit`/`view` (Ночи №3–5) — синонимы «Редактор»/«Комментатор»; их поведение не меняется и не расширяется молча.
- Автор элемента `BaseEl.by` ставит только хаб или сервер (`u:<userId>` из сессии, `c:<id>` от P2P-хаба); имя, цвет, курсор и присланные клиентом идентификаторы автором не являются. Нет `by` — элемент владельца. `by` — поле хаба: переносится в `hostElement`/`guardedElement`/`mergeStale` и не входит в `contentSignature`.
- Решение о правке чужих элементов принимает `src/element-guard.ts` в хабах и в `POST /api/projects/:id/patch`; клиент лишь не предлагает недоступные действия. Отклонённая правка возвращается отправителю исправляющим `{t:'patch'|'project', by: -1}`.
- Токен ссылки — 24 символа (≥ 128 бит из криптостойкого генератора), именной адрес — 3–23 символа; именной адрес разрешается сервером и не раскрывает токен. Освобождённый адрес никогда не достаётся другому аккаунту.
- Окно «Поделиться» (`src/share-dialog.ts`): не пересоздавать узлы формы при обновлении списков; «Сейчас на доске», «Отправлено приглашение» и «Есть доступ» — разные списки; не обещать «отозвать доступ у человека», если отзывается один способ входа; не выдавать `127.0.0.1` за адрес для гостей.
