# Выкладка веб-доски

Доска и API используют `https://board.abaxboard.ru`. Корень `https://abaxboard.ru` пока продолжает обслуживать приложение и старые ссылки; общего лендинга ещё нет. База и изображения остаются в `/var/lib/abax`, секреты - в `/etc/abax/abax.env`.

Перед переключением нужны DNS-запись A для `board`, сертификат HTTPS и регистрация новых OAuth-адресов. В Google OAuth добавьте `https://board.abaxboard.ru/api/auth/google/callback`. В Telegram Login Widget добавьте origin `https://board.abaxboard.ru` и callback `https://board.abaxboard.ru/api/auth/telegram/callback`. Старые адреса сохраняйте для отката. Проверяйте вход у обоих провайдеров после выкладки.

Сборка клиента для VPS: `DOSKA_API_URL=https://board.abaxboard.ru npm run build`; сборка сервера: `npm run server:build`. Перед выкладкой выполните `npm run typecheck`, `npm run typecheck:tests`, `npm test` и подходящие E2E. Не меняйте `apiUrl` в `package.json`: пустое значение сохраняет работу офлайн-сборок. При сборке desktop и Android адрес облака задаётся отдельно; ранее установленные приложения продолжают использовать адрес, зашитый при их сборке.

Готовьте независимый каталог релиза в `/opt/abax/releases/`, не меняя текущий. После сборки сохраните копии конфигурации nginx и `/etc/abax/abax.env` с исходными правами, а также проверьте резервную копию базы и изображений. В серверном env точечно задайте `PUBLIC_WEB_URL` и `PUBLIC_API_URL` новому адресу и добавьте старые origin в `ALLOWED_ORIGINS`, не удаляя существующие значения и секреты. Nginx должен обслуживать оба домена, проксировать API и WebSocket, а сертификат должен покрывать соответствующие имена. Проверьте `nginx -t` до reload.

Атомарно переключите `/opt/abax/current` на подготовленный релиз и перезапустите `abax.service`. Проверьте HTTPS, API, входы, приглашения и совместную работу на обоих адресах. Для отката верните прежний симлинк, конфигурацию и env из резервных копий, проверьте `nginx -t`, перезапустите сервис и перечитайте nginx. База и файлы не должны удаляться при выкладке или откате.

Данные браузера и локальная сессия принадлежат конкретному origin: при первом открытии нового домена может потребоваться повторный вход, локальные доски автоматически не переносятся. До вывода корневого домена из эксплуатации нужно отдельно проверить старые ссылки, старые приложения и экспорт локальных данных. Версионированные гостевые ссылки Electron на GitHub Pages сохраняются для совместимости версий протокола.

## Кабинет репетитора

Для tutor.abaxboard.ru используется та же сборка dist, Node-сервер, база и JWT_SECRET, что и для доски. Настройте DNS и TLS для домена кабинета, добавьте его в server_name веб-приложения и проксируйте /api и WebSocket на тот же backend. Маршруты /tutor и /?route=tutor открывают кабинет на основном домене. На отдельном домене кабинет открывается на /.

Для общего входа укажите COOKIE_DOMAIN=.abaxboard.ru в окружении сервера. В production сервер ставит Secure и HttpOnly. Добавьте https://tutor.abaxboard.ru в ALLOWED_ORIGINS для возвратов после входа. Отдельная cookie панели администратора сохраняет свою область действия.

В BotFather для Mini App задайте HTTPS-адрес кабинета. На сервере нужен TELEGRAM_BOT_TOKEN этого бота. Данные запуска проверяет POST /api/auth/tma. В npm run dev:cloud без настроенного токена и при включённом ABAX_DEV_AUTH тесты подписывают данные ключом abax-dev-mini-app. На production этот ключ отключён.
