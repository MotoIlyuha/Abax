# Панель управления Abax

Панель для `https://admin.abaxboard.ru` собирается в `dist-admin/`. Nginx раздаёт её и проксирует запросы того же origin в существующий Node-сервер. Сервер использует общую базу Abax. В сборке панели нет адреса API, реквизитов почты или ЮKassa.

## Локальный запуск

Установите зависимости из lockfile для Node 22. Для тестового запуска используйте отдельный каталог данных.

```powershell
npm ci
$env:DATA_DIR = '.data/admin-local'
$env:ABAX_DEV_AUTH = '1'
$env:ABAX_ADMIN_ORIGIN = 'http://127.0.0.1:5180'
npm run server
```

Для создания первого **локального** аккаунта выполните в другом терминале. Эти запросы идут на обычный порт API, где код dev-входа возвращается в JSON.

```powershell
$api = 'http://127.0.0.1:8787/api/auth/email'
$email = 'admin@abax.test'
$login = Invoke-RestMethod "$api/start" -Method Post -ContentType 'application/json' -Body (@{email=$email} | ConvertTo-Json)
$user = Invoke-RestMethod "$api/verify" -Method Post -ContentType 'application/json' -Body (@{email=$email;code=$login.devCode} | ConvertTo-Json)
$user.user.id
```

Перезапустите первый процесс с `$env:ABAX_ADMIN_ACCOUNTS = '<выведенный ID>=admin@abax.test'`. В другом терминале запустите `npx vite --config admin/vite.config.ts` и откройте `http://127.0.0.1:5180` по этому точному адресу. Код входа панели будет в консоли Node. При другом порте Node задайте панели `ABAX_ADMIN_API_TARGET`, сохраняя значение `ABAX_ADMIN_ORIGIN` равным адресу браузера.

Проверка собранной панели локально:

```sh
npm run typecheck
npm run typecheck:tests
npm test
npm run test:e2e -- admin.spec.ts billing.spec.ts night4-cloud-auth.spec.ts night6-links.spec.ts
npm run server:build
npx vite build --config admin/vite.config.ts
npx vite preview --config admin/vite.config.ts
```

## Назначение администратора и сессия

1. Войдите в нужную учётную запись на доске и в разделе профиля привяжите вход по почте. Это относится и к аккаунтам с Google: для панели нужна отдельно подтверждённая почта для входа Abax.
2. Получите `user.id` и `user.email` из авторизованного `GET /api/me` на доске и сверьте их с нужной учётной записью. Укажите назначение `ID=почта` в `ABAX_ADMIN_ACCOUNTS` в env сервера. Несколько назначений разделяйте запятой. Удаление назначения и перезапуск сервера прекращают доступ по этому ID.
3. Настройте отправку почты через существующий SMTP или почтовый webhook. Оставьте `ABAX_DEV_AUTH` выключенным в продакшене. На панели войдите с привязанной почтой и кодом из письма.

Панель использует текущие маршруты почтового входа, а её код действует только на origin панели. Node сопоставляет уже существующий аккаунт и его подтверждённую почту с назначением. Перепривязка почты на доске прекращает доступ по прежнему назначению до изменения конфигурации сервера. Сессия доски, токен устройства, принадлежность доски, подписка и приглашения прав на панель не дают. Аргумент `ABAX_ADMIN_ORIGIN` обязателен и должен быть точным HTTPS-origin без слеша. Для серверных тестов и локальной разработки допустим loopback HTTP.

Cookie `__Host-abax_admin` имеет `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, срок восемь часов и выдаётся без `Domain`. База хранит только хеш токена. Выход удаляет серверную сессию. Сервер проверяет ID на каждом запросе и требует точный `Origin` и `Content-Type: application/json` для записи, включая вход и выход. Административные ответы не разрешают CORS и не кешируются.

## Выкладка на VPS

1. Подготовьте независимый релиз Node по [инструкции для доски](DEPLOY_BOARD.md) и положите содержимое `dist-admin/` в `/var/www/abax-admin/releases/<id>/`. Nginx должен иметь доступ на чтение. Подготовьте симлинк `/var/www/abax-admin/current` для атомарного переключения.
2. Сделайте согласованную резервную копию БД с SQLite Backup API или действующей службой резервного копирования. Проверьте копию на отдельном экземпляре, затем обновите Node. V10 применяется при открытии БД и добавляет журнал, сессии, флаг промокода и дату обработки платежа. Для старых промокодов отключение отсутствует. Для старых платежей дата обработки остаётся неизвестной. Даты в панели показываются в часовом поясе браузера.
3. В серверном env задайте `ABAX_ADMIN_ORIGIN=https://admin.abaxboard.ru` и утверждённые назначения `ABAX_ADMIN_ACCOUNTS`. Сохраните настройки входа доски, включая `PUBLIC_API_URL`, `PUBLIC_WEB_URL` и адреса OAuth. Проверьте `NODE_ENV=production`, `TRUST_PROXY=1` и loopback для Node (`HOST=127.0.0.1`).
4. Когда DNS и сертификат будут готовы, подключите [виртуальный хост](../deploy/admin/nginx.conf). Включите [блокировку маршрутов панели](../deploy/admin/block-on-board.conf) на `board.abaxboard.ru`, `abaxboard.ru`, `www.abaxboard.ru` и других публичных входах в тот же API. Сохраните точный публичный Host на каждом существующем прокси доски. Для панели проксируются только `/api/admin/` и два маршрута почтового входа. Проверьте путь к сертификату и запустите `nginx -t` перед reload.
5. Проверьте HTTPS и вход разрешённым аккаунтом, код 401 без cookie на origin панели, 404 для пути панели на доменах доски, прежние входы и гостевые ссылки доски. Для проверки записи используйте специально подготовленный тестовый аккаунт или промокод. Проверьте появление операции в журнале.

Панель платежей показывает состояние последней обработки сервером. Для ЮKassa оно меняется после действующего webhook или штатной сверки из аккаунта покупателя. Чтение панели не запускает повторные оплаты или заявки к ЮKassa. В журнале промокоды представлены псевдонимом на основе серверного секрета. При замене `JWT_SECRET` старые записи сохранят прежние псевдонимы.

## Откат

Для отката панели верните прежний симлинк статики или отключите её виртуальный хост, уберите `ABAX_ADMIN_ACCOUNTS` и перезапустите Node. Оставьте блокировку маршрутов панели на публичных доменах доски. SQLite V10 сохранит журнал, выданные тарифы, блокировки и результаты активаций.

Если нужен откат Node, верните предыдущий релиз и настройки службы. Если отключались промокоды, сначала временно закройте `POST /api/billing/promo` на всех публичных входах (например, `location ^~ /api/billing/promo { return 503; }`). Старый Node не учитывает `disabled_at`. Возобновите погашение на V10-совместимой версии. Перед переключением проверьте `nginx -t`. Отдельно проверьте доску и гостевые ссылки после переключения. Возврат кода не требует обратной миграции. Снимок БД используйте для аварийного восстановления с учётом всех записей после момента снимка.
