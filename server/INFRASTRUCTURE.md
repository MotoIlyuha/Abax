# Инфраструктура Abax

Доска и API: https://board.abaxboard.ru. Старые адреса abaxboard.ru и www.abaxboard.ru сохраняются. Ретранслятор: wss://relay.abaxboard.ru, проверка: https://relay.abaxboard.ru/health. Старый relay.95-174-92-156.sslip.io нужен уже установленным приложениям и старым приглашениям; его нельзя отключать без отдельной миграции.

Relay работает как `abax-relay.service` за nginx. На VPS с 2 ГиБ ОЗУ systemd ограничивает его память: `MemoryHigh=512M`, `MemoryMax=768M`. При превышении жёсткого предела процесс может быть перезапущен и активные комнаты потеряны. Существующие соединения также обрываются при обновлении relay; проверять нагрузку и масштабировать до появления заметного числа пользователей.

## Данные и резервные копии

База: `/var/lib/abax/abax.db`, изображения: `/var/lib/abax/assets`. Служба `abax-backup.timer` ежедневно запускает `/usr/local/sbin/abax-backup`: SQLite Backup API делает согласованный снимок, включая данные WAL; архив также содержит каталог изображений и секретный env. Хранится семь архивов в `/var/backups/abax`, доступ только root. Архивы чувствительны: в них есть секреты и пользовательские данные.

Проверка: `systemctl status abax-backup.timer abax-backup.service`, `journalctl -u abax-backup --since '2 days ago'`. Восстановление проверять в отдельном закрытом временном каталоге, извлекая базу и изображения из одного архива; выполнить `PRAGMA integrity_check` и сверить файлы с записями `assets`. Не заменять рабочую базу во время проверки.

`abax-monitor.timer` каждые пять минут проверяет службы, HTTPS, диск и свежесть архива (36 часов); порог свободного места - 2 ГиБ или 15%. Результат: `journalctl -u abax-monitor -n 30`. Это только локальный журнал, внешние уведомления пока не настроены. Копии на том же диске не защищают от потери VPS. Для внешней копии нужен выбранный провайдер, публичный ключ шифрования, сохранённый вне VPS закрытый ключ, доступ на запись и проверенный ключ хоста или сертификат. Не хранить закрытый ключ и пароли в репозитории или переписке. Проверить расшифровку и восстановление вне VPS до включения расписания и политики хранения.

Для подготовки зашифрованного файла предусмотрен `server/encrypt-backup.sh`: передать ему путь к готовому архиву, публичному ключу OpenPGP и закрытому каталогу назначения. Он не перезаписывает существующие копии. Передачу в хранилище и автоматическую очистку нельзя включить до выбора протокола и политики хранения; при настройке нужно передавать только зашифрованный файл и проверять результат загрузки.

## Публикация

Версии гостевых страниц с GitHub Pages 2.5.0-2.11.0 скопированы в `/var/www/abax-guests/releases/20261121-ghpages/v/`, текущий каталог указывает симлинк `/var/www/abax-guests/current`. Доступны на `https://board.abaxboard.ru/v/<версия>/`. Уже установленные приложения используют GitHub Pages; адрес в Electron пока оставлен прежним. Автоматической публикации новых гостевых версий на VPS нет: прежде чем менять адрес в Electron, нужно обеспечить её до выпуска и проверить все ресурсы и работу приглашений.

Для ручной публикации новой версии сначала запомнить `readlink -f /var/www/abax-guests/current`, подготовить новый независимый каталог в `/var/www/abax-guests/releases/` и скопировать в него прежний набор через `cp -aL`. Добавить сборку только в отсутствующий каталог `v/<версия>/`, проверить `index.html`, все его относительные ресурсы и право чтения nginx. Убедиться, что старые версии присутствуют и не изменились. Создать рядом новый симлинк на подготовленный каталог и атомарно заменить `current` командой `mv -T`; затем проверить ссылки через HTTPS и подключение гостя. Для отката таким же способом вернуть симлинк на сохранённый путь. Существующие версии и GitHub Pages не удалять и не перезаписывать.

`release.yml` пока публикует гостевые страницы на GitHub Pages, а отдельный `site.yml` направлен в прежний Yandex Object Storage, не на VPS. Публикация сайта VPS автоматом не настроена. Для новой версии подготовить независимый каталог `/opt/abax/releases/<id>`, включить актуальные утверждённые изменения, выполнить обе проверки типов, `npm test`, подходящие E2E, сборку `DOSKA_API_URL=https://board.abaxboard.ru npm run build` и `npm run server:build`. Проверить резервную копию, конфигурацию и стенд до переключения. Атомарно заменить `/opt/abax/current`, перезапустить `abax`, проверить HTTPS, API, вход и комнаты. Для отката вернуть симлинк на прежний релиз и перезапустить службу. Каталоги `/var/lib/abax` и `/etc/abax` не входят в релиз и при откате не удаляются. Изменения схемы БД требуют отдельной проверки обратной совместимости: возврат кода сам по себе не откатывает миграции.

Прямые загрузки описаны в `deploy/downloads/README.md`. Новый workflow загрузок ещё нужно выполнить при следующем выпуске. Windows и Android при сборке получают API доски из `DOSKA_API_URL`; Android подписывается прежним ключом, иначе обновление поверх старой установки невозможно. Офлайн-сборки без этой переменной сохраняют прежнее поведение.
