## 1. Цель Ночи №5
Четыре блока:
1. **Облако без швов**: пустая стартовая доска не попадает в облако и тихо заменяется облачным проектом при входе; индикатор синхронизации в шапке; живая синхронизация между собственными устройствами владельца; копия при настоящем офлайн-конфликте.
2. **Живая комната**: всплывающие уведомления (Activity Pills) и встроенный чат участников.
3. **Приглашения**: права до создания ссылки, живое изменение прав у подключённых гостей, свой лимит гостей (Pro/Tutor) и экран «Комната заполнена», приглашения по почте.
4. **Присутствие**: краевые курсоры, аватары на страницах, «Позвать всех сюда», Pro-тумблер «Автопереход за мной», защита скрытых страниц.

## 2. Облако без швов (клиент: `src/sync-state.ts`, `src/cloud-sync.ts`, `src/main.ts`, `src/cloud-room.ts`, `src/state.ts`)

### 2.1. Стартовая заглушка
- При первом запуске `src/main.ts` создаёт `blankProject('Проект 1')` и сразу сохраняет (сейчас он тут же уходит в облако). Имя заглушки — **«Проект 1»**, а не «Без названия».
- Новое: при создании заглушки на запуске её id запоминается в `localStorage['doska.starter']`. Метка снимается при первом `pushHistory()` в этом проекте, при переименовании и при любом изменении настроек/прав проекта.
- Чистый предикат `isPristineStarterProject(project, starterId)` в `src/sync-state.ts`: `project.id === starterId`, одна страница, `elements.length === 0`, нет комментариев, `name === 'Проект 1'`, имя страницы `'Страница 1'`, нет `permissions`, `icon`, `pinned`, фон/сетка по умолчанию.
- `cloud-sync.ts`: пока предикат истинен — `PUT` этого проекта не отправляется (`doPush` → `'skipped'`, `syncAll` его пропускает).
- Замена: после `syncAll()` при активной сессии (запуск, событие `doska:account-changed` после входа) — если открыт проект-заглушка, а сервер вернул хотя бы один проект пользователя, заглушка удаляется только локально (без `DELETE` на сервер и без записи в `pendingDeletes`), открывается проект с максимальным `updatedAt` через `openFresh` + `openProject`, `doska.last` обновляется. Без тоста.

### 2.2. Индикатор синхронизации в шапке
- Тип `SyncStatus = 'hidden' | 'synced' | 'syncing' | 'offline' | 'limit'` и чистая функция `syncStatusOf(input)` в `src/sync-state.ts` (вход: облако включено, проект только на устройстве по лимиту, есть ли запросы в полёте/ожидание, последняя ошибка сети, проект — заглушка, автор в облачной комнате и её соединение).
- `CloudStorage` получает `status(id)` и подписку `onStatus(fn)`; `flushNow()` = текущий `flush()` + сброс паузы повтора.
- Кнопка `#sync-indicator` в группе проекта шапки (`index.html`), иконка + `title`/`aria-label`:
  - `hidden` — облака нет (`cloudStorage() === null`), гость, просмотр по ссылке, проект-заглушка;
  - `synced` — «Сохранено в облаке»;
  - `syncing` — «Синхронизация…» (анимация; без анимации при `.no-motion`/reduced motion);
  - `offline` — «Сохранено на устройстве (офлайн)», клик → `flushNow()`;
  - `limit` — «Только на устройстве (превышен лимит тарифа)», клик → поповер с пояснением тарифов. Источник — ответ 403 `plan-limit-projects` / `plan-limit-pages` (существующие коды).
- Пока автор в облачной комнате, статус берётся из соединения комнаты: открыта → `synced`, переподключение → `offline`.

### 2.3. Свои устройства (ноутбук + планшет)
- `connectOwnerRoom()` подключает владельца к комнате своего облачного проекта, если **есть приглашение или пользователь вошёл в аккаунт** (не анонимный). Анонимной сессии второе устройство недоступно — комната без приглашения не нужна.
- Хаб: опция `multiHost` (включается только в `server/cloud-room-manager.ts`) — несколько соединений с `isHost` вместо отказа 4409. Хосты не занимают гостевые слоты. Бесплатная комната закрывается для гостей, когда уходит **последний** хост.
- Когда вкладка снова видна (`visibilitychange`) или окно получает `focus`: если соединение комнаты закрыто — переподключение; если комнаты нет — `openFresh(текущий)` и мягкое применение более новой серверной версии (без своих несохранённых правок). Не чаще раза в 5 с.

### 2.4. Настоящий офлайн-конфликт
- Чистый модуль `src/sync-conflict.ts` (разрешён серверу): `contentSignature(project)` — хеш (cyrb53 по JSON) содержимого автора **без** «живых» полей (реакции, ввод учеников, комментарии; тот же набор, что `liveSignature` в `server/projects.ts`).
- Клиент хранит `doska.syncBase.<id>` — подпись последней версии, совпавшей с сервером (после успешного PUT — подпись отправленного, после загрузки — подпись загруженного).
- `PUT /api/projects/:id` принимает необязательное `baseSig`. Если `expectedRev < rev` на сервере **и** `contentSignature(серверная) !== baseSig` → `409 rev-conflict` `{ rev }` без записи. Без `baseSig` (старые клиенты, Electron) — прежнее слияние `mergeStale`.
- Клиент на `409 rev-conflict`: локальная версия сохраняется как новый проект (новый id) с именем `«<Имя> (копия с устройства)»` (уходит в облако обычным путём, при лимите — остаётся на устройстве); основной проект загружается с сервера и, если открыт, перезагружается на холсте; тост «Проект обновился с другого устройства. Ваши офлайн-правки сохранены в копию» с кнопкой «Открыть копию».

## 3. Протокол хабов (`src/room-host.ts` ⇄ `electron/room.cjs`, зеркально)
Все изменения вносятся **в оба хаба одновременно**; `PROTO` не меняется (новые поля и сообщения необязательны, старые клиенты их игнорируют).

| Сообщение | Направление | Правила |
|---|---|---|
| `{t:'chat', text}` | клиент → хаб | `text.trim()`, 1..500 символов (длиннее — отказ, не обрезка), не более 5 сообщений за 3 с от участника (лишние молча отбрасываются) |
| `{t:'chat', id, by, name, cursorId, text, ts}` | хаб → все | кольцевой буфер 100 сообщений в памяти комнаты; в `init` — поле `chat: [...]`; в проект/файл/БД не пишется |
| `{t:'view', pageId, vx, vy, vz}` | клиент → хаб | центр экрана в мировых координатах и зум; конечные числа, `vz` в пределах зума приложения; хранится в `Client.view`, попадает в `users` |
| `{t:'summon', pageId, vx, vy, vz}` | хост → хаб → гости | только от хоста; гостям, у которых `pageId` не `hidden` |
| `{t:'follow-host', enabled}` | хост → хаб → все | только если тариф комнаты ≠ `free` (с учётом `limitsEnforced`/`enforceLimits` как сейчас); состояние в `init` (`followHost`) |
| `{t:'denied', reason:'room-full', maxGuests, planLimited}` + закрытие | хаб → гость | `planLimited: true` — лимит Free (код **4402**), `false` — лимит автора (код **4430**) |

### 3.1. Маскировка скрытой страницы
`usersSnapshot` строится **для каждого получателя**: если участник стоит на странице, скрытой для получателя, у него в снимке `pageId: null`, `cursor: null`, `view: null`, `selection: []`, `hiddenPage: true`. Правило общее для всех участников (не только для хоста). Указки уже фильтруются (`relayPointer`).

### 3.2. Живые права страниц
- Хаб запоминает `permissions.pageRights` проекта. Когда принятый от хоста `{t:'project'}` (или `pushProject` с сервера) меняет право страницы, у каждого гостя право этой страницы ставится в новое значение (личные права других страниц не трогаются), затем `pushRights(uid)` (существующий механизм).
- Облако: `invite.pageRights` у новых приглашений пустые (матрица прав — только `project.permissions.pageRights`); старые записи с непустыми правами продолжают работать как раньше.
- Смена роли/копирования у ссылки — существующий `POST /api/invites` (обновление на месте) + новое событие `onAccessChanged({kind:'invite-updated', token})` → комната пересчитывает `default` у соединений с этим токеном и вызывает `setRights`.

### 3.3. Лимит гостей
- `ProjectPermissions.maxGuests?: number | null` (`null`/`0`/нет — без ограничений). `sanitizePermissionsForPlan`: на `free` поле отбрасывается; на pro/tutor — целое 1..50.
- Эффективный лимит хаба: `min(лимит тарифа, permissions.maxGuests || ∞)`, если хабу не передан явный `options.maxGuests` (браузерный хост без лимитов — `Infinity`, как сейчас).

## 4. Сервер (`server/db.ts`, `server/invites.ts`, `server/invite-routes.ts`, `server/projects.ts`, `server/cloud-room-manager.ts`, `server/auth-flows.ts`)

### 4.1. Миграция V3
```sql
ALTER TABLE invites ADD COLUMN kind TEXT NOT NULL DEFAULT 'link';   -- 'link' | 'email'
ALTER TABLE users ADD COLUMN google_email TEXT;                      -- только при email_verified = true
CREATE TABLE project_email_invites (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  host_user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  email TEXT NOT NULL,                 -- нормализованный, нижний регистр
  role TEXT NOT NULL,                  -- 'edit' | 'view'
  token TEXT NOT NULL UNIQUE REFERENCES invites(token),
  status TEXT NOT NULL DEFAULT 'pending', -- pending | accepted | declined | revoked
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_email_invites_project_email ON project_email_invites(project_id, email);
CREATE INDEX idx_email_invites_email ON project_email_invites(email, status);
```
- `activeInviteOf` / `GET /api/invites?projectId` и `POST /api/invites` работают только с `kind = 'link'`.
- Вход через Google сохраняет `google_email` (если `email_verified`).

### 4.2. Приглашения по почте
- Каждое приглашение по почте — своя строка `invites` (`kind='email'`, своя роль, `page_rights_json='{}'`) + строка `project_email_invites` с тем же токеном. Повторное приглашение того же адреса обновляет роль и снова отправляет письмо (не чаще раза в 10 минут на адрес).
- `POST /api/projects/:id/email-invites` `{email, role}` — владелец; 400 `bad-email`, 400 `self-invite`, 404, лимит 20/час на владельца; письмо через `app.mailer` (нет почты → 503 `mail-disabled`) со ссылкой `<PUBLIC_WEB_URL>/?route=collab&token=…`. Ответ — запись.
- `GET /api/projects/:id/email-invites` — список (без отозванных).
- `DELETE /api/projects/:id/email-invites/:inviteId` — `status='revoked'`, `invites.revoked=1`, `onAccessChanged({kind:'invite-revoked', token})` (существующее отключение сокетов кодом 4403).
- `GET /api/me/invites` — `pending` приглашения, где `email` = `users.email` или `users.google_email`; поля: `id`, `projectId`, `projectName`, `hostName`, `role`, `token`, `createdAt`. Анонимному — пустой список.
- `POST /api/me/invites/:inviteId/respond` `{action:'accept'|'decline'}` — только адресату; `accept` → `{ token }`, `decline` → статус `declined` (токен не отзывается).
- Письмо и записи — без пользовательского HTML: текстовое письмо, имя проекта и автора — как текст.

### 4.3. Комната
- `multiHost: true` для облачных комнат (§2.3); `leave()` закрывает гостей бесплатной комнаты только после ухода последнего хоста.
- Лимит гостей §3.3, отказ — `{t:'denied', reason:'room-full', maxGuests, planLimited}` + код 4402/4430.
- Событие `invite-updated` (§3.2).

## 5. Activity Pills — `src/activity-pills.ts`
- Контейнер `#activity-pills` (в `index.html`), справа сверху под шапкой; `pointer-events: none`, кроме кнопок внутри; не более 3 пилюль (старая уходит), автоскрытие 3.5 с, `aria-live="polite"`; анимация отключается `.no-motion` и `prefers-reduced-motion`.

## 7. Приглашения в интерфейсе — `src/invite-ui.ts`, `src/link-view-ui.ts`, `src/collab.ts`, `src/main.ts`
- Права до ссылки: в окне «Совместная работа» роль, «Разрешить копирование», матрица страниц и (Pro/Tutor) «Максимум гостей» видны и до создания ссылки; меняют `state.project.permissions` через `pushHistory` (как прочие правки проекта) и локальный стейт роли; «Создать ссылку-приглашение» отправляет выбранную роль.
- Гость теряет текущую страницу (`{t:'project'}` без неё): `cancelActiveInteraction()` (новое в `src/controller.ts`: отменить рисование, перетаскивание, выделение рамкой, закрыть редактор текста без коммита незавершённого жеста) + `clearSelection`; переход на ближайшую доступную страницу (следующая, иначе предыдущая) + пилюля «Автор скрыл страницу, на которой вы находились».

Появилась страница — баннер скрывается, она открывается. Клиент обязан переносить проект без страниц (не падать, не сохранять).
- `#room-full-modal`: «В комнате сейчас максимум участников (N из N)»; пояснение — лимит бесплатного тарифа автора (`planLimited`) или ограничение автора; «Попробовать снова» (повторное подключение) и «Открыть только для чтения» (`loadInvite` → `openInviteView`, кнопка скрыта, если видимых страниц нет). Заменяет уведомления 4402/4430 для облачной комнаты; P2P/LAN/ретранслятор показывают модалку с теми же текстами.
- Почта у автора: поле адреса, роль, «Пригласить», список со статусом и «Отозвать». У приглашённого: блок «Приглашения для вас» на домашнем экране (лаунчер проектов) + точка-бейдж на кнопке профиля; карточка «<Автор> приглашает вас на доску «<Название>»», «Присоединиться» (переход `?route=collab&token=…`) / «Отклонить». Запрос `GET /api/me/invites` — на запуске после `syncAccount`, при `doska:account-changed` и при открытии домашнего экрана (не чаще раза в 30 с).

## 8. Присутствие — `src/edge-pointer.ts`, `src/presence.ts`, `src/collab.ts`, `src/controller.ts`, `src/app.ts`
- `animateCameraTo(wx, wy, zoom?, durationMs = 320)` в `src/controller.ts`: easeInOutCubic, прерывается любым жестом пользователя; мгновенно при `.no-motion`/reduced motion.
- Клиент шлёт `{t:'view'}` при смене страницы и после остановки камеры (дебаунс 250 мс).
- Краевые курсоры (чистая `computeEdgePointer(sx, sy, rect, padding)` → `null` | `{x, y, angle}`): участник на моей странице, курсор (или центр его экрана, если курсора нет) вне безопасной области (отступы от шапки, левой панели, дока страниц). DOM `.collab-edge-pointer` — SVG курсора участника, повёрнутый по лучу; бейдж имени горизонтален; `opacity .65`, при hover 1 + имя. Клик → `animateCameraTo` к курсору с моим зумом (если курсора нет — к `view` участника с его зумом). Не рисуется для участников с `hiddenPage` и «отошедших» дольше 45 с.
- Аватары: `getParticipantInitials(name)` (1–2 заглавные буквы, эмодзи/пустое → «?»), фон `badgeBg`, текст `badgeText` пресета; у вкладок дока страниц (до 3 + «+N») и в списке участников. Клик → страница участника + `animateCameraTo`. Хост с `hiddenPage` — «На скрытой странице», клик → пилюля «Автор сейчас на скрытой странице».
- «Позвать всех сюда» (только хост): страница не скрыта → `summon`; скрыта → поповер «Открыть для редактирования и позвать» / «Открыть для просмотра и позвать» / «Отмена» (меняет `permissions.pageRights`, отправляет проект — §3.2, затем `summon`).
- «Автопереход участников за мной» (Pro/Tutor; у Free тумблер с плашкой Pro): гость следует за `pageId`/`view` хоста из `users`, пока хост не на скрытой странице; у хоста на скрытой странице плашка «Эта страница скрыта — участники остались на предыдущей странице». Гость, сам сменивший страницу, продолжает следовать при следующей смене страницы хостом.

## 11. Locked Decisions
Нумерация вопросов предполётного согласования 1–8 сохранена; приняты рекомендации «по умолчанию» с **Уточнениями** по результатам сверки с кодом.

**А. Организация**
0.1. `night/5` — от текущего `main` (2.9.0). Первый коммит: `SPEC_NIGHT5.md`, `TASKS.md`, `AGENTS.md`; `NIGHT_LOG.md` → `NIGHT_LOG_NIGHT4.md`, новый `NIGHT_LOG.md`.
0.2. Базовая линия — по последней записи `NIGHT_LOG.md`: 1096 unit/server и 299 E2E; агент перепроверяет её первым прогоном и пишет фактические числа.
0.3. Новых npm-зависимостей нет.

**Б. Решения по вопросам**
1. **Заглушка.** Да, но **Уточнение:** имя заглушки — «Проект 1» (`blankProject` в `src/main.ts`); стек Undo не переживает перезапуск, поэтому вместо «пустого undoStack» — метка `doska.starter`, снимаемая первым `pushHistory()`/переименованием (§2.1). Заглушка удаляется только локально.
2. **Свои устройства на Free.** Да: сессии владельца (тот же `userId`) — хосты на любом тарифе, гостевой слот не занимают. **Уточнение:** хаб сейчас отвечает второму хосту 4409 — нужна опция `multiHost` (только облако); владелец подключается к комнате и без приглашения, если вошёл в аккаунт (§2.3).
3. **Офлайн-конфликт.** Копия только при настоящем конфликте. **Уточнение:** сервер не отвечает 409 на устаревшую ревизию (сливает `mergeStale`), поэтому конфликт определяется по `baseSig` — подписи содержимого автора без живых полей (§2.4); иначе правки учеников/реакции давали бы ложные копии.
4. **Чат.** Да: 100 сообщений в памяти хаба, в `init`; не в SQLite и не в `.doska`.
5. **Живые права у созданной ссылки.** Да. **Уточнение:** отдельный PATCH не нужен — `POST /api/invites` уже обновляет активное приглашение на месте; добавляется событие `invite-updated` для комнаты. Права страниц живут только в `project.permissions.pageRights` (§3.2).
6. **«Открыть только для чтения».** Да: существующий `openInviteView` без WebSocket, только не скрытые страницы, клонирование — по правам автора.
7. **Почта незарегистрированного.** Да. **Уточнение:** вход через Google сейчас не сохраняет адрес — добавляется `users.google_email` (только `email_verified`), совпадение по `email` или `google_email`.
8. **Краевой курсор.** Да: центр — курсор участника с моим зумом; без курсора — его `view` с его зумом. Остриё по лучу, бейдж горизонтален.

**В. Прочие уточнения аудита**
9. Код лимита тарифа при синхронизации — существующие `plan-limit-projects` / `plan-limit-pages` (не `project_limit_exceeded`).
10. Коды закрытия не перенумеровываются: 4402 — лимит Free, 4430 — лимит автора; причина — в `{t:'denied'}` перед закрытием.
11. `maxGuests` — только в `ProjectPermissions` (одно место правды), колонка `invites.max_guests` не нужна.
12. Вход/выход/смена профиля для пилюль вычисляются из `{t:'users'}`; новых сообщений для них нет.
13. Маскировка скрытой страницы — для любого участника, не только хоста (§3.1).
14. Каждое приглашение по почте — отдельный токен в `invites` (`kind='email'`); ссылка из письма работает как обычная ссылка-приглашение (доступ по токену, не по адресу).
15. `src/sync-conflict.ts` добавляется в список модулей `src/`, разрешённых серверу.
16. `cancelActiveInteraction` и `animateCameraTo` — новые функции `src/controller.ts` (сейчас их нет).
