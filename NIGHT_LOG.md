## TASK-05 — способы входа: почта, Telegram, Google, dev-провайдеры (готово)
- `server/mailer.ts` без npm-зависимостей (Решение 8): `memoryMailer`, `consoleMailer`, `webhookMailer` (POST JSON `{to, subject, text}`, Bearer-токен), `smtpMailer` на `node:net`/`node:tls` (EHLO → STARTTLS, если предложен (или обязателен при `requireTls`) → AUTH PLAIN → MAIL FROM → RCPT TO → DATA → QUIT; письмо — MIME base64, тема RFC 2047; переводы строк в адресах отвергаются), `mailerFromEnv` (`MAIL_WEBHOOK_URL` или `SMTP_*`).
- `server/identity.ts`: `resolveIdentity(db, identity, mode, current, now)` — `link` (нужна сессия; способ у другого → 409 `identity-taken`), `login` (есть у X — аноним сливается в X; нет — аноним получает способ на месте; иначе новый пользователь). Имя провайдера пишется только при `name_custom = 0`. Старый `POST /api/auth/telegram` переписан на `resolveIdentity` (поведение то же).
- `server/auth-flows.ts`: `GET /api/auth/providers`; почта — `POST /api/auth/email/start` (код `randomInt`, в БД SHA-256 от `email:code`, 10 минут, 5/час на адрес и 20/час на IP, ошибка отправки → 502 `mail-failed`) и `/verify` (5 попыток → 429 `too-many-attempts`, просрочен → `code-expired`); потоки — `POST /api/auth/flow` → `{flowId, secret, url}`, `GET /api/auth/dev/start`, `GET /api/auth/google/start` (PKCE S256) и `/callback` (обмен кода через внедряемый `fetch`, проверка `aud`/`iss`/`exp`/`sub`), `POST /api/auth/flow/complete` (сравнение SHA-256 секрета за постоянное время, поток одноразовый; для Telegram — проверка подписи `#tgAuthResult`).
- Безопасность `returnTo`: только http(s) без логина в URL и только разрешённые origin — `publicWebUrl`, `publicApiUrl`, `ALLOWED_ORIGINS`, при `devAuth` — `localhost`/`127.0.0.1`. Решение: origin из заголовка `Host` в разрешённые НЕ входит (его можно подделать прямым запросом), он используется только для ссылки на сам сервер (`apiOrigin`), если `PUBLIC_API_URL` не задан.
- Dev-провайдеры (Решение 5): `devAuth` — код почты в ответе (`devCode`) и в логе; Telegram/Google без настоящих ключей → `/api/auth/dev/start` сразу входит тестовым аккаунтом (Telegram `100000001` «Тестовый Telegram», Google `dev-google-1` «Тестовый Google») и возвращает на `returnTo#abaxAuth=`. `scripts/dev-cloud.mjs` ставит `ABAX_DEV_AUTH=1`, если не заданы оба `TELEGRAM_BOT_TOKEN` и `GOOGLE_CLIENT_ID`; провайдер с настоящим ключом работает по-настоящему. В `server/index.ts` `devAuth` никогда не включается при `NODE_ENV=production`. Без почтового транспорта в dev — `consoleMailer`.
- Окружение: `vite.config.ts` (dev-сервер), `server/index.ts`, `server/.env.example` (`GOOGLE_CLIENT_ID/SECRET`, `PUBLIC_API_URL`, `ALLOWED_ORIGINS`, `MAIL_WEBHOOK_*`, `SMTP_*`, `ABAX_DEV_AUTH`), `server/README.md`.
- Клиент `src/auth.ts`: `authProviders` (кэш), `canRedirectAuth` (http(s) и не Android), `startEmail`, `verifyEmail` (сначала анонимная сессия — доски устройства переходят в аккаунт), `startRedirect` (поток + секрет в `sessionStorage['doska.authPending']` + `resume` визарда), `completePendingAuth` (хеш `#abaxAuth=`/`#tgAuthResult=` убирается всегда; без ожидающего потока — игнор), `logout` (новый аноним, профиль остаётся), `authErrorText` — тексты ошибок по-русски. `saveSession` в `api-client.ts`. После входа/выхода без перезагрузки — событие `doska:account-changed`, `main.ts` перезапускает фоновую синхронизацию проектов.
- Наблюдение: `morph-pages.test.ts › открытие: лоток держится видимым…` (анимация на таймерах, 3 с) один раз не уложился при полном прогоне под нагрузкой; 2 полных прогона подряд и отдельный — зелёные. Перепроверяю в TASK-08.
- Тесты: `tests/server/mailer.test.ts` (8, поддельный SMTP-сервер), `tests/server/auth-email.test.ts` (8), `tests/server/auth-flows.test.ts` (9), `tests/unit/auth.test.ts` (8). Всего 1073.

## TASK-06 — визард первого входа (готово)
- `src/cursor-picker.ts` (общий с «Профилем»): превью (образец объекта с рамкой и 8 ручками в `selectionColor`, рамка выделения области, курсор и бейдж с именем) + сетка 14 плиток (`role=radio`, стрелки по сетке; у Pro без права — бейдж `PRO`) + плашка «Доступно в подписке Pro» с кнопкой «Вернуться к бесплатному курсору» (логика — `onboarding-logic.ts`).
- `src/onboarding.ts`: одно окно, лента из двух шагов; `transform: translateX(0 | -50%)` + подстройка высоты, 300 мс; при `prefers-reduced-motion` / `no-motion` — без анимации (`ob-instant`); неактивный шаг — `inert` и `aria-hidden`.
  - Шаг 1 открывается всегда первым: Почта / Telegram / Google, «Продолжить без входа» и под ней пояснение (Решение 4). Без облака клик по любому способу — сообщение «Облачный сервер не подключён в этой сборке — нажмите «Продолжить без входа»», кнопки остаются. Нативная сборка (Telegram/Google), способ не настроен на сервере, нет связи — свои сообщения там же. Почта раскрывает форму «адрес → Получить код → код → Войти», в dev — подсказка «Режим разработки: код NNNNNN».
  - Шаг 2: «← Назад», имя (вошёл и у аккаунта есть «настоящее» имя — подставлено; иначе пусто с placeholder из смешных имён), сетка курсоров с превью, блок «Привязать ещё способ входа» (только вошедшему и только непривязанные способы + «Это можно сделать в любой момент в Настройках → Профиль»), «Продолжить».
  - Tab (без Shift) в пустом поле — `preventDefault`, placeholder → `value`, каретка в конец; второй Tab — штатно (Решение 34). Enter / «Продолжить» — `resolveName`, профиль `{name, cursorId: choice.saved, onboarded: true}`, при облаке — `pushProfile`.
  - Решение: ✕ / Esc сохраняют то же, что «Продолжить» (имя из поля или placeholder, курсор — последний разрешённый выбор; если курсор не трогали — `default`), т. е. Решение 33 для нетронутого окна.
  - Клавиатура: обработчик на корне окна (фаза всплытия) — сначала срабатывают обработчики полей (Tab-подстановка, Enter), затем Esc и Tab по кругу, дальше окна клавиши не уходят; отдельный перехват на `window` (фаза захвата) — для нажатий, пришедших не из окна.
  - Найдено при написании: если перехватывать на `window` в фазе захвата и останавливать там (как в окне настроек), обработчики поля имени не получили бы Tab/Enter — поэтому разделение выше.
- `main.ts`: на обычной доске (не просмотр по ссылке) `completePendingAuth()` до открытия проекта; после скрытия `#startup` — `startOnboarding`: возврат от провайдера из визарда → шаг 2 (или шаг 1 с ошибкой), из настроек → `openProfileAfterAuth` (раздел «Профиль», TASK-07), иначе — визард, если знакомство не пройдено. Гостю (`?room`, `#relay`, `/j/:token`) визард не показывается (ветка гостя возвращается раньше).

## После ночи: настоящий вход через Telegram (OpenID Connect)
- По документации Telegram (core.telegram.org/widgets/login, discovery `oauth.telegram.org/.well-known/openid-configuration`) у Telegram есть официальный OIDC; прежний поток Ночи №4 (`oauth.telegram.org/auth?bot_id=…&return_to=…` и `#tgAuthResult`) нигде не задокументирован — заменён.
- Новый поток: `/api/auth/telegram/start` → `https://oauth.telegram.org/auth` (`client_id` = ID бота, `scope=openid profile`, `state`, PKCE S256) → `/api/auth/telegram/callback` → `https://oauth.telegram.org/token` (Basic `client_id:client_secret`, `code_verifier`) → проверка подписи `id_token` по JWKS (обязательна по документации; новый `server/jwks.ts` на `node:crypto`: RS256, ES256, EdDSA, кэш на час, повторная загрузка при новом `kid`) → `iss`, `aud`, `exp` → аккаунт по числовому claim `id` (совпадает с `tg_id` прежних входов через виджет) → возврат `#abaxAuth=`.
- `nonce` для Telegram не передаётся: в документации он есть только в опциях JS-библиотеки, не как параметр адреса; защита — `state` + PKCE.
- Настройки: `TELEGRAM_CLIENT_SECRET` (обязателен), `TELEGRAM_CLIENT_ID` (по умолчанию — из `TELEGRAM_BOT_TOKEN`); dev-заглушка Telegram — пока нет `TELEGRAM_CLIENT_SECRET`. Старый `POST /api/auth/telegram` (данные виджета, HMAC) оставлен. Клиент больше не разбирает `#tgAuthResult`.
- Инструкция (@BotFather → Login Widget → Allowed URLs, Client ID/Secret) — `server/README.md`, раздел «Вход через Telegram». Принимает ли Telegram `http://localhost` в Allowed URLs, документация не говорит — для разработки может понадобиться https-туннель.
- Тесты: `tests/server/jwks.test.ts` (3), в `auth-flows.test.ts` старый тест Telegram заменён на OIDC с настоящей RS256-подписью (чужой ключ, `aud`, `iss`, просрочен, нет `id`, отказ пользователя) + «без Client Secret — выключен». Всего 1093; E2E `night4-*` — 13 зелёных. Smoke `dev:cloud` с `TELEGRAM_CLIENT_SECRET` — редирект на `oauth.telegram.org/auth` с верными параметрами.
