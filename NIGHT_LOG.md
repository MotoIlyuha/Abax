## TASK-06 — клиентская облачная синхронизация (готово)
- `src/cloud-sync.ts`: `createCloudStorage(base, opts)` — обёртка над `BoardsStorage` устройства. `save` пишет локально как раньше, отмечает проект «есть правки для облака» (`doska.syncDirty.<id>`) и через 2 с шлёт `PUT /api/projects/:id` с `expectedRev` = `lastSyncedRev`; картинки: `extractProjectAssets` → `uploadMissingAssets` → в PUT только `asset://`, локальный проект остаётся с полными data URL. `flush()` (на `visibilitychange` — сразу), повторы после сбоя сети по таймеру (5/15/60 с), 409 `missing-assets` — догрузка и один повтор, 403 по лимиту — проект остаётся локальным до перезапуска и один раз показывается тост, 409 `id-taken` — проект тихо получает новый id (хранилище, открытая доска, список, `doska.last`), прочие 4xx — без повторов. Отправки одного проекта идут по очереди.
- `openFresh(id)` (вызывается при открытии с главной и при запуске): если у проекта есть `lastSyncedRev`, спрашивает сервер; версия новее и своих несохранённых правок нет — берёт серверную (с ответами учеников) и сохраняет локально; правки с обеих сторон — остаётся локальная, при отправке сервер сливает (`mergeStale`); 404 на сервере — локальный проект уйдёт как новый; нет сети — локальный.
- `syncAll()` после запуска и получения тарифа: сначала отложенные удаления (`doska.syncDeletes`), затем список `GET /api/projects`; проекты, которых нет на устройстве, передаются главному экрану (`doska:projects-changed`, `mergeRemoteMetas`), а проекты устройства без облачной копии или с неотправленными правками уходят по одному; при сбое сети цикл прерывается и повторяется. Открытие проекта «только с сервера» скачивает его и сохраняет на устройстве; `load` без локальной копии берёт его только владельцу (роль host), без сохранения.
- Удаление: `DELETE` на сервере; без сети — запоминается и выполняется позже, такой проект не появляется в списке сервера.
- Пока автор в облачной комнате проекта (`setCloudRoomProject`, подключит TASK-07), PUT этого проекта не уходит; после выхода — уходит накопленное.
- Без адреса сервера (по умолчанию) `initCloudSync()` ничего не подключает: хранилище прежнее, запросов нет — все старые тесты не затронуты. ## Исправления после финального прогона
- Нашёлся пробел в протоколе слияния (редкая гонка в `cloud-sync.test.ts`): после PUT, в котором сервер добавил чужой ввод (ответы учеников, реакции, комментарии), клиент считал, что видел эту ревизию, и следующий PUT с `expectedRev` = текущей стирал этот ввод. Теперь `PUT` отвечает `merged: true`, если сохранённое отличается от присланного живыми полями, а клиент в этом случае запоминает ревизию на единицу меньше: следующие сохранения снова сливаются на сервере, а при открытии (своих правок нет) подтягивается серверная версия. Тесты: `merged` в `projects.test.ts`, новый сценарий в `cloud-sync.test.ts`.
- `cloud-sync`: отправка, стоявшая в очереди за предыдущей, пропускается, если все правки уже ушли (раньше `flush()` мог послать лишний PUT той же версии); `force` — только для проектов без облачной копии при начальной синхронизации.
- `electron-main.test.ts`: тест первого порта допускает «ближайший свободный» — порт мог занять параллельный тест (временные порты из того же диапазона).
