## 1. Цель Ночи №4

После Ночи №3 у пользователя нет ни имени, ни профиля: автор в комнате — всегда «Автор», гость — «Гость NN», цвета участникам раздаёт хаб, выделение всегда фирменно-синее, клиентского входа в аккаунт нет вовсе.

**Цель**:
1. Профиль пользователя (имя + выбранный курсор), локально и на сервере.
2. Каталог персональных курсоров (`CursorPreset`): форма/узор курсора, цвет выделения, цвет бейджа; 6 бесплатных и 8 Pro.
3. Курсор пользователя над холстом (инструмент `select`), на кнопке `select` панели инструментов и у других участников совместной работы.
4. Вход в аккаунт: Почта (код), Telegram, Google; привязка дополнительных способов; dev-провайдеры для `npm run dev:cloud`.
5. Двухшаговый визард первого входа со «слайд»-анимацией и раздел настроек «Профиль».

## 2. Модель профиля (клиент)

- Ключ `doska.profile`: `{ name: string, cursorId: string, onboarded: boolean, updatedAt: number }`.

## 3. Каталог курсоров — `src/cursors.ts` (чистый модуль, без DOM; разрешён серверу)

### 3.1. Тип
```ts
interface CursorPreset {
  id: string; name: string; tier: 'free' | 'pro';
  /** Заливка стрелки: цвет или узор (SVG-defs строятся каталогом). */
  fill: string; outline: string; pattern?: 'geometry' | 'cosmos' | 'neon' | 'holo' | 'pixel' | 'gold' | 'flame' | 'aurora';
  selectionColor: string; badgeBg: string; badgeText: string;
  effect: 'none' | 'glow' | 'trail' | 'sparkle'; effectColor: string;
}
```

### 3.2. Пресеты
**Free (6)**: `default` «Классика» (белый с тёмным контуром; выделение и бейдж — фирменный `#3273f5`), `graphite` «Графит», `mint` «Мята», `coral` «Коралл», `lavender` «Лаванда», `amber` «Янтарь».
**Pro (8)**: `geometry` «Геометрия», `cosmos` «Космос», `neon` «Неон», `hologram` «Голограмма», `pixel` «Пиксель», `gold` «Золото», `flame` «Пламя», `aurora` «Аврора» — узор внутри стрелки (`<pattern>`/`<linearGradient>` в `defs`) и эффект (`glow` — свечение, вшитое в SVG; `trail` — шлейф затухающих частиц; `sparkle` — искры).

### 3.3. Функции
- `CURSOR_PRESETS`, `CURSOR_IDS`, `DEFAULT_CURSOR_ID = 'default'`, `isCursorId(v)`, `cursorPreset(id)` (неизвестный — `default`).
- `canUseCursor(id, plan)`: free-пресет — всегда; pro — при `plan !== 'free'`.
- `cleanCursorId(raw, allowPro)`: неизвестное/не строка — `undefined`; Pro без права — `'default'`.
- `cursorSvg(id, { size? })`: самодостаточная SVG-разметка (строится только из констант каталога — никаких пользовательских данных); id элементов `defs` уникальны для пресета (`abc-<id>-…`).
- `cursorCss(id)`: `url("data:image/svg+xml,…") 3 2, default` — 32×32, горячая точка на кончике стрелки.
- `contrastRatio(a, b)` (WCAG): `selectionColor` к белому ≥ 3:1, `badgeText` к `badgeBg` ≥ 4.5:1 — проверяется тестом для каждого пресета.

## 4. Отображение у себя

1. **Курсор над холстом**: в `src/controller.ts` курсор инструмента `select` — `cursorCss(myCursorId())`; меняется сразу при смене профиля/тарифа. Остальные инструменты — как раньше.
2. **Цвет выделения**: в `src/renderer.ts` все литералы `#3273f5` рамки выделения, ручек (включая ручку поворота), общей рамки нескольких объектов и прямоугольной рамки выделения областью (`state.marquee`) заменяются на `mySelectionColor()`. Направляющие, рамки страниц, пины комментариев и `--accent` интерфейса не меняются.
3. **Кнопка `select`**: `toolDef('select').icon` — цветная мини-копия курсора (`cursorSvg`, класс `cursor-icon`) во всех местах, где показываются иконки инструментов (панель, панель группы, кнопка группы, призрак перетаскивания, редактор панели, горячие клавиши). При смене курсора панель перестраивается.
4. **Эффекты** — `src/cursor-fx.ts`: отдельный `<canvas id="cursor-fx">` поверх холста (`pointer-events: none`), свой `requestAnimationFrame`, работает только пока есть живые частицы; не больше 160 частиц на всё; выключен при `prefers-reduced-motion` и выключенном переключателе «Motion анимации» (`body.no-motion`). Свой эффект — при движении мыши (`pointerType === 'mouse'`) с инструментом `select`.

## 5. Совместная работа

1. `cursorId` (необязательный) передаётся при подключении по всем путям: параметр `cursor` WS локальной сети (`startCollab` → `electron/share.cjs`), `hello` облачной комнаты (`cloudRoomTransport` → `server/cloud-room-manager.ts`), `hello` через ретранслятор (`cloudTransport` → `relay-host.ts`, `electron/cloud-link.cjs`), `hello` BroadcastChannel (`local-transport.ts`), автор браузерного хоста (`browser-host.ts`).
2. Хабы (`src/room-host.ts` и зеркало `electron/room.cjs`): `AttachOptions.cursorId`, `AttachOptions.allowProCursor` (по умолчанию `true`); значение — через белый список (`cleanCursorId`); в снимке `users` у участника есть `cursorId` (если задан). Поле `color` остаётся (старые клиенты).
3. Новое сообщение `{ t: 'profile', name?, cursorId? }`: смена имени/курсора на лету; хаб нормализует и рассылает `users`.
4. Cloud Room проверяет тариф по сессии: Pro-курсор гостя без сессии или на free понижается до `default`. Хабы P2P/LAN/ретранслятора проверяют только белый список.
5. Имя: автор — имя профиля, иначе «Автор»; гость — `?name=` из адреса, затем имя профиля, затем `Гость NN`.
6. Чужие курсоры (`src/collab.ts`): постоянные DOM-узлы по `userId` (не пересоздаются на каждое сообщение): стрелка `cursorSvg` + бейдж (`span`, `textContent`, цвета `badgeBg`/`badgeText`); участник без `cursorId` — классическая стрелка и бейдж цвета `color` от хаба. «Отошёл» — серый бейдж, полупрозрачная стрелка, без эффекта. Эффекты чужих курсоров — через `cursor-fx`.
7. Рамка чужого выделения — `selectionColor` пресета участника (без `cursorId` — `color` хаба), пунктир как раньше.
8. Протокол обратно совместим: `PROTO` не меняется, старые хабы и клиенты игнорируют новые поля.

## 6. Сервер: профиль

1. Миграция V2 (`server/db.ts`): `users.cursor_id TEXT NOT NULL DEFAULT 'default'`, `users.name_custom INTEGER NOT NULL DEFAULT 0`, `users.email TEXT` (уникальный индекс), `users.google_sub TEXT` (уникальный индекс); таблицы `email_codes` и `auth_flows` (раздел 7).
2. `isAnonymous` — нет ни `tg_id`, ни `email`, ни `google_sub`.
3. `userInfo` дополняется: `cursorId`, `nameCustom`, `email`, `telegram: boolean`, `google: boolean`.
4. `PATCH /api/me` `{ displayName?, cursorId? }`: имя — `normalizeName`, пустое → 400 `bad-name`, ставит `name_custom = 1`; курсор не из белого списка → 400 `bad-cursor`; Pro-курсор при эффективном тарифе free → 403 `plan-cursor` (кроме `devAuth`). Ответ — как `/api/me`. CORS разрешает `PATCH`.
5. Вход через провайдера заполняет `display_name` только если `name_custom = 0`. Длина имени на сервере — до 40 (`MAX_NAME`).

## 7. Вход и привязка способов входа

### 7.1. Общая модель
- `resolveIdentity(db, provider, ident, mode, currentUser)`:
  - `link` (нужна сессия): способ уже у другого пользователя → 409 `identity-taken`; иначе записывается текущему.
  - `login`: способ есть у пользователя X → текущий аноним сливается в X (`mergeUsers`); нет — текущий аноним получает способ «на месте»; нет сессии или текущий не аноним — создаётся новый пользователь.
- `GET /api/auth/providers` → `{ email, telegram, google, dev, telegramBotId? }`.

### 7.2. Почта
- `POST /api/auth/email/start { email }`: адрес проверяется и приводится к нижнему регистру; 6-значный код (`crypto.randomInt`), в БД только SHA-256; срок 10 минут; лимиты 5 писем в час на адрес и 20 в час на IP (429 `rate-limited`). Ответ `{ ok: true, devCode? }` (`devCode` только при `devAuth`).
- `POST /api/auth/email/verify { email, code, mode }`: до 5 неверных попыток (дальше 429 `too-many-attempts`, код удаляется); просрочен → 400 `code-expired`; неверен → 400 `bad-code`. Успех — `resolveIdentity` и ответ сессии.
- `Mailer` (`server/mailer.ts`, без npm-зависимостей): `memoryMailer` (тесты), `consoleMailer` (dev), `webhookMailer` (POST JSON на `MAIL_WEBHOOK_URL`), `smtpMailer` (`node:net`/`node:tls`: EHLO, STARTTLS, AUTH PLAIN, MAIL FROM, RCPT TO, DATA). Без настроенного транспорта и без `devAuth` почта недоступна (`providers.email = false`).

### 7.3. Telegram и Google (переход на сервер)
1. Клиент: `POST /api/auth/flow { provider, mode, returnTo }` (с сессией) → `{ flowId, secret, url }`; `secret` и состояние визарда — в `sessionStorage`; переход `location.assign(url)`.
2. `returnTo` — только http(s) и только разрешённые origin: `publicWebUrl`, сам сервер, `ALLOWED_ORIGINS`, а при `devAuth` — `localhost`/`127.0.0.1`. Иначе 400 `bad-return`.
3. Google: `GET /api/auth/google/start?flow=` → 302 на Google (Authorization Code + PKCE S256, `state = flowId`); `GET /api/auth/google/callback` меняет код на токены (token endpoint по TLS), проверяет `aud`, `iss`, `exp`, берёт `sub`, `email`, `name` → `resolveIdentity` → результат в `auth_flows` → 302 на `returnTo#abaxAuth=<flowId>`.
4. Telegram: `url` = `https://oauth.telegram.org/auth?bot_id=…&origin=…&request_access=write&return_to=<returnTo>`; Telegram возвращает `#tgAuthResult=<base64>` — клиент отправляет его в `POST /api/auth/flow/complete { flowId, secret, telegram }`; сервер проверяет подпись (существующий `verifyTelegramLogin`).
5. `POST /api/auth/flow/complete { flowId, secret }` → ответ сессии (или ошибка `identity-taken`, `flow-expired`, `bad-flow`); поток одноразовый, живёт 10 минут; сравнивается SHA-256 секрета.
6. **Dev-провайдеры** (`devAuth`: `ABAX_DEV_AUTH=1`; в `npm run dev:cloud` включены по умолчанию, если не заданы `TELEGRAM_BOT_TOKEN`/`GOOGLE_CLIENT_ID`): `url` → `GET /api/auth/dev/start?flow=` — мгновенно разрешает тестовый аккаунт (Telegram `id 100000001`, «Тестовый Telegram»; Google `sub dev-google-1`, `dev.google@example.com`, «Тестовый Google») и делает 302 на `returnTo#abaxAuth=<flowId>`.
7. Старый `POST /api/auth/telegram` продолжает работать (режим `login`, теперь через `resolveIdentity`).
8. В нативных сборках (Electron, Android: адрес страницы не http(s)) Telegram и Google показывают сообщение «Вход через … пока доступен только в веб-версии — войдите по почте».

### 7.4. Клиент — `src/auth.ts`
`authProviders()`, `startEmail(email)`, `verifyEmail(email, code, mode)`, `startRedirect(provider, mode, resume)`, `completePendingAuth()` (на запуске: `#abaxAuth=` / `#tgAuthResult=` + ожидающий поток → сессия; хеш убирается `history.replaceState`), `logout()`, `account()` (последний `/api/me`), `onAccountChange(fn)`. После входа: тариф применяется, профиль синхронизируется (раздел 8), облачная синхронизация перезапускается.

## 8. Синхронизация профиля
1. Вход выполнен и `nameCustom` у аккаунта — имя и курсор аккаунта переходят в локальный профиль (сервер главнее). Иначе непустое локальное имя и курсор уходят на сервер (`PATCH /api/me`).
2. Каждое изменение профиля в UI при настроенном облаке — `PATCH /api/me` (ошибки тихие; `plan-cursor` — курсор остаётся только локально).
3. При запуске (`syncPlanFromServer`) — то же правило п. 1.
4. Выход: новый анонимный токен устройства (как раньше); локальные имя и курсор остаются.

## 9. Визард первого входа — `src/onboarding.ts`

1. Показывается на обычном запуске доски, если `!getProfile().onboarded`, после скрытия `#startup`. Не показывается гостю (`?room`, `#relay`, `/j/:token`), в режиме просмотра по ссылке и в окне демонстрации.
2. Одно модальное окно, два шага в горизонтальной ленте; переключение — `transform: translateX` ~300 мс с подстройкой высоты; при reduced motion / `no-motion` — мгновенно. Клавиатура доске не достаётся, Tab не выходит из окна.
3. **Шаг 1** (открывается всегда первым): заголовок, кнопки **Почта**, **Telegram**, **Google**, кнопка **«Продолжить без входа»** и под ней текст: «Без входа доступны рисование, экспорт, участие по ссылкам и хранение досок в этом браузере. Вход нужен для облачной синхронизации между устройствами, сохранения досок при очистке браузера и подписки Pro».
   - Почта раскрывает форму (адрес → «Получить код» → 6 цифр → «Войти»); в dev — подсказка с `devCode`.
   - Без адреса API клик по любому способу показывает в окне: «Облачный сервер не подключён в этой сборке — нажмите «Продолжить без входа»». Кнопки не скрываются.
   - Способ не настроен на сервере / нативная сборка — понятное сообщение там же.
4. **Шаг 2** (после любого выбора, «слайд» влево): «← Назад» (обратный «слайд»), поле имени, сетка курсоров, превью, блок привязки, «Продолжить».
   - Имя: вошёл и у аккаунта есть имя — подставлено; иначе пустое с placeholder из `randomFunnyName()`.
   - `Tab` в пустом поле (без `Shift`): `preventDefault`, placeholder → `value`, каретка в конец; при заполненном — штатно. «Продолжить»/`Enter` с пустым полем — имя из placeholder.
   - Сетка: 6 free + 8 Pro (у пользователя без права — бейдж `PRO`). Превью: образец объекта с рамкой и ручками в `selectionColor`, курсор и бейдж с именем.
   - Pro без права: превью + плашка «Доступно в подписке Pro» и кнопка «Вернуться к бесплатному курсору»; «Продолжить» в этот момент сохраняет последний выбранный бесплатный курсор; клик по бесплатному — обычное состояние.
   - Вошёл: компактный блок «Привязать ещё способ входа» (ещё не привязанные Почта / Telegram / Google) и пояснение «Это можно сделать в любой момент в Настройках → Профиль».
5. ✕ или `Esc` — как «Продолжить без входа» с именем из placeholder и курсором `default`; `onboarded = true`.
6. Возврат после перехода к провайдеру — визард открывается на Шаге 2 с сохранёнными (в `sessionStorage`) именем и курсором; ошибка входа — сообщение на Шаге 1.

6. Механизм — полный переход на сервер и возврат с одноразовым идентификатором потока во фрагменте + `POST /api/auth/flow/complete` с секретом из `sessionStorage`; состояние визарда — в `sessionStorage`.
7. Telegram — через `oauth.telegram.org/auth` без скрипта виджета, проверка подписи — существующий HMAC.
8. Почта — 6-значный код, 10 минут, 5 попыток, в БД только хеш; лимиты 5/час на адрес и 20/час на IP. **Уточнение (Б.5):** без `nodemailer` и новых npm-зависимостей: интерфейс `Mailer`; dev/тесты — консоль/память; прод — webhook (HTTP) или SMTP-адаптер на `node:net`/`node:tls`.
9. Google — Authorization Code + PKCE на сервере (`GOOGLE_CLIENT_ID/SECRET`), `id_token` из ответа token endpoint; в тестах `fetch` подменяется.
10. Electron/Android — только почта; Telegram/Google показывают сообщение (доделка — Ночь №5).
11. Колонки `email`, `google_sub` рядом с `tg_id` (уникальные индексы) + таблица `email_codes` (+ `auth_flows`); `isAnonymous` — нет ни одного способа.
12. Способ у другого зарегистрированного аккаунта → 409 `identity-taken`; анонимная сессия при входе сливается, как раньше.
13. Отвязка и удаление аккаунта — вне скоупа; есть «Выйти».
14. Выход — новый анонимный токен; локальные имя и курсор сохраняются; Pro без права откатывается к `default` (выбор сохраняется).
15. `name_custom`; провайдер заполняет имя только если оно не задано пользователем; при входе сервер главнее, далее — `PATCH /api/me`; имя 1–40 символов (`normalizeName`), серверный `cleanName` — до 40.

**В. Каталог курсоров**
16. Free: «Классика», «Графит», «Мята», «Коралл», «Лаванда», «Янтарь»; Pro: «Геометрия», «Космос», «Неон», «Голограмма», «Пиксель», «Золото», «Пламя», «Аврора». Палитры — в `src/cursors.ts`.
17. У каждого Pro ровно один эффект (`glow` / `trail` / `sparkle`); эффекты на отдельном канвасе только при движении; выключены при `no-motion`/reduced motion; у чужих курсоров тоже, с общим лимитом частиц.
18. Аппаратный курсор: SVG 32×32, горячая точка на кончике, запасной `default`; тёмный контур у светлых пресетов.
19. Кастомный курсор — только у `select` (и в режимах просмотра); над ручками тоже.
20. `selectionColor`: рамка выделения, ручки, ручка поворота, общая рамка, рамка выделения областью. Направляющие, рамки страниц, пины, `--accent` — без изменений.
21. Контраст: `selectionColor` к белому ≥ 3:1, текст бейджа ≥ 4.5:1 — unit-тест.
22. Иконка `select` — цветная мини-копия курсора во всех местах; подсказка без изменений.
23. **Уточнение (В.8):** Pro у free-пользователя: превью + плашка «Доступно в подписке Pro» + кнопка «Вернуться к бесплатному курсору»; «Продолжить» не блокируется — сохраняется последний выбранный бесплатный курсор; клик по бесплатному возвращает обычное состояние. После истечения тарифа выбранный Pro сохраняется, действует `default`.
24. Право: клиент — `userPlan() !== 'free'` или dev-режим; сервер — `PATCH /api/me` с Pro без тарифа → 403 `plan-cursor` (при `devAuth` разрешено); в dev без серверного тарифа Pro хранится локально.

**Г. Совместная работа**
25. Cloud Room проверяет тариф по сессии (без сессии/free → `default`); P2P/LAN/ретранслятор — только белый список.
26. `cursorId` — необязательное поле, `PROTO` не меняется; без `cursorId` — цвет хаба.
27. `{t:'profile', name, cursorId}` — смена на лету.
28. Автор — имя профиля вместо «Автор» (и в подписи комментариев); гость — `?name=` → профиль → `Гость NN`.
29. Чужое выделение — `selectionColor` пресета участника, пунктир; одинаковые пресеты допустимы.
30. «Отошёл» — серый бейдж, полупрозрачная стрелка, без эффекта.

**Д. Онбординг**
31. Показывается всем без `doska.profile.onboarded`, включая существующих пользователей (один раз).
32. Веб, Electron, Android; не показывается гостю, в просмотре по ссылке и в окне демонстрации.
33. ✕ / `Esc` = «без входа» с именем из placeholder и курсором `default`.
34. **Уточнение (Д.4):** `Tab` (без `Shift`) в пустом поле — `preventDefault`, placeholder → `value`, каретка в конец; при заполненном — штатно; «Продолжить»/`Enter` с пустым полем — имя из placeholder.
