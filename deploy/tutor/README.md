# Выкладка Abax Tutor

Релизный workflow собирает `dist` и `dist-server`, передаёт их на VPS `tutor.abaxboard.ru`, атомарно переключает `/opt/abax/current` и проверяет фактическую версию по HTTPS. Публикация GitHub Release, сайта и Pages ждёт успешной проверки Tutor. Если ключ или деплой недоступен, workflow останавливается до публикации остальных площадок.

## Ограниченный доступ для GitHub Actions

Используйте отдельный ключ Ed25519. Workflow хранит приватный ключ только в секрете репозитория `ABAX_TUTOR_DEPLOY_SSH_KEY`. На VPS ключ привязан к принудительной команде приёма архива с отключёнными shell, PTY и port forwarding. Команда может запускать только проверенный сценарий выкладки; приватный ключ root для Actions не используется.

Для первичной настройки или ротации ключа:

1. Создайте отдельную пару ключей `ssh-keygen -t ed25519 -N "" -f abax_tutor_deploy`.
2. Скопируйте `deploy/tutor/` во временный каталог VPS под `/tmp` с root-доступом.
3. Под root установите сценарии и публичный ключ:

   ```sh
   bash /tmp/abax-tutor-deploy/setup-vps.sh "$(cat /tmp/abax-tutor-deploy/abax_tutor_deploy.pub)" /tmp/abax-tutor-deploy
   ```

4. Сохраните файл `abax_tutor_deploy` как секрет репозитория `ABAX_TUTOR_DEPLOY_SSH_KEY`; публичную часть можно удалить после установки.

`known_hosts` содержит закреплённый ключ VPS. При смене ключа сначала проверьте новый отпечаток через панель провайдера, затем обновите файл и повторите выпуск.

## Проверки и откат

Перед переключением сервер сохраняет SQLite-снимок с `quick_check`, архив `/var/lib/abax/assets`, env и конфигурации nginx. Новая версия распаковывается в отдельный каталог; ссылка `current` переключается атомарно. Сценарий проверяет статический asset, API и состояние сервиса. При локальной проверке ошибки он возвращает предыдущую ссылку и перезапускает сервис на прежнем каталоге. Затем job проверяет asset и API на публичном домене. GitHub Release и остальные публичные сайты не публикуются, пока эта проверка не завершилась успешно.
