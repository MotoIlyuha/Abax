\# SPEC\_NIGHT2.md — Техническая спецификация: Интеграция UI, Сети и Оверлеев (Ночь №2)



\## Контекст

В ветке `night/1` реализованы и покрыты юнит-тестами базовые модули: `src/file.ts`, `src/limits.ts`, `src/router.ts`, `src/delta.ts`, `src/room-host.ts`, `src/asset-store.ts`, `src/comments.ts`, `src/task-element.ts`.

Задача Ночи №2 — подключить эти модули к пользовательскому интерфейсу (`src/app.ts`, `src/main.ts`, `src/renderer.ts`) и сетевому слою (`src/collab.ts`, `src/collab-transport.ts`), а также покрыть сценарии сквозными тестами.

\## Спецификация задач



\### 1. Сохранение реакций при Undo / Redo (`src/state.ts`, `src/comments.ts`)

\- \*\*Проблема из Ночи №1\*\*: `reactions` хранятся на элементах (`BaseEl.reactions`), но `toggleElementReaction` не пишет шаги в историю `pushHistory` (чтобы `Ctrl+Z` не отменял чужие реакции). Из-за этого при вызове `undo()` или `redo()` старый снимок элементов затирает актуальные реакции.

\- \*\*Решение\*\*:

&#x20; - В `src/comments.ts` добавить чистую функцию `preserveElementReactions(snapshotElements: readonly Element\[], currentElements: readonly Element\[]): Element\[]`, которая переносит актуальное поле `reactions` с `currentElements` на `snapshotElements` при совпадении `id`.

&#x20; - Вызывать `preserveElementReactions` внутри `undo()` и `redo()` в `src/state.ts` перед применением снимка истории.



\### 2. Интеграция Роутера, Режимов Просмотра и Клонирования (`src/app.ts`, `src/main.ts`, `src/router.ts`)

\- При инициализации приложения (`src/main.ts` / `src/app.ts`) и при `popstate` / `hashchange`:

&#x20; - Разбирать текущий URL через `parseBoardUrl(window.location.href)`.

&#x20; - Если маршрут `view-project` или `view-page`:

&#x20;   - Выставлять `state.linkMode = route.mode`.

&#x20;   - Переводить холст в режим только для чтения (блокировать инструменты рисования/редактирования/удаления, но разрешать панорамирование, зум и ввод ответа в `TaskEl`).

&#x20;   - Если `route.mode === 'view-page'`, скрывать док страниц (`#pages-dock`) и фиксировать активную страницу `route.pageId` (если она есть в проекте).

&#x20;   - Показывать аккуратную плашку режима просмотра с кнопкой \*\*«Клонировать проект»\*\* только в режиме `view-project` и только при `canCloneCurrentProject() === true`.

&#x20;   - Нажатие \*\*«Клонировать проект»\*\*: создает полную копию текущего проекта с новым `id = uid()`, очищает `state.linkMode = null`, применяет `projectTaskForRole(el, 'guest')` (если клонирует гость/зритель, чтобы не утекли скрытые ответы), сохраняет проект в `storage` и убирает параметры просмотра из URL через `history.replaceState`.

&#x20; - Если в маршруте задан непустой `focusIds`:

&#x20;   - После первичной загрузки/разметки холста вызывать `focusElementsOnBoard(route.focusIds, viewportW, viewportH)`.

\- Добавить генерацию ссылок в UI (в диалог «Поделиться» и/или контекстное меню выделенных объектов):

## Locked Decisions

Нумерация = номера вопросов предполётного согласования. Все ответы приняты как «по умолчанию»; три уточнения — в конце.

Процесс
1. Задач семь, по одной на раздел: TASK-01…TASK-07 (порядок 1→7).
2. Ветка `night/2` от `night/1`.
3. Первый коммит: `AGENTS.md` (реальные имена, ссылка на SPEC_NIGHT2), Locked Decisions, `TASKS.md`.
4. Решения записаны здесь.
5. Playwright — на последней задаче (canvas-edges, night2-features и затронутые спеки); обязательные для закрытия задач — typecheck, typecheck:tests, npm test.
